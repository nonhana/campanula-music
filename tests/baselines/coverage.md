## 路由校准

`pnpm test:coverage:calibrate` 从既有 `session.test.ts` 选择“未登录打开 App”：真实请求 `/api/account`，返回未登录状态。报告中账号处理函数有调用计数；`/api/playlists/[id]/name` 没有请求、函数计数全部为零。只导入模块的顶层命中不能代替处理函数命中。源码映射缺失、收不到 SSR 数据或这两项对照不成立，命令会失败。

Vite 的独立 module runner 用绝对路径 `sourceURL`；标准采集器过滤掉这些脚本。`tests/coverage/runtime.ts` 从同一次 V8 快照收集它们以及实际执行代码，`provider.ts` 读取执行时的内联源码映射，用与 Vitest 相同的 AST 转换库映回源码，再与普通 Vitest 数据合并。导入绑定等编译产物不算产品语句。`ssr-raw/`、`ssr.json` 和最终逐文件报告保留完整链条。

## 复测

顺序运行，避免争用 World 的 Kit 输出：

```sh
# 当前实现，全部原用例 + 新断言和基础设施检查
pnpm test:coverage
pnpm test:coverage:calibrate

# 同一采集器，只运行原来的产品断言，重现补断言前的产品分区
CAMPANULA_COVERAGE_DIR=.reports/coverage-before pnpm test --coverage \
  --exclude tests/unit/suites.test.ts -t '^(?!.*换到还不知道时长)'
```

要重现原调研口径，在开工 SHA 的隔离副本安装依赖和 `@vitest/coverage-v8@5.1.0`，使用当时根 Vite 配置运行：

```sh
pnpm exec vitest run --coverage \
  --coverage.include='src/**/*.ts' --coverage.include='src/**/*.svelte' \
  --coverage.exclude='src/**/*.d.ts'
```

这个旧采集器会再次漏掉独立 SSR，不将其作为当前服务端阈值。当前 `partitions.json` 同时保存分母、Node/V8/Vitest 版本、所选范围和未采集说明，CI 上传同一 SHA 的测试与校准报告。
