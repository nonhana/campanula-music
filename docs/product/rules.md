# 核心业务规则与运行时不变量

本文件记录 Campanula 播放队列、听歌打卡、下载、曲库同步、会话与延迟提交的核心规则。

## 规则 ①–⑫

| 编号 | 场景                                                        | 规定行为                                                                                     |
| ---- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| ①    | 播放队列为空时选“下一首播放”或“加入播放队列”                | 直接开始播放                                                                                 |
| ②    | 插播、下一首播放、加入播放队列的歌已在队列中                | 挪到目标位置，只保留一份，播放来源更新为新来源；若就是当前正在播放的那首，保持不变、不从头放 |
| ③    | 随机模式下执行“下一首播放”“加入播放队列”                    | 按字面执行：下一首紧排当前之后，加入排在队列末尾，不混入随机序列                             |
| ④    | 被插播打断的那首歌                                          | 当场按已播秒数打卡，插播完后不回原断点续播                                                   |
| ⑤    | 连续多次执行“下一首播放”                                    | 后加入的先放（每次紧插在当前歌曲后）                                                         |
| ⑥    | 歌曲播放到一半关闭 App 时的听歌打卡                         | 不算结束；累计已听秒数随播放进度保存在本机，下次放完合并打一次卡                             |
| ⑦    | 按歌单删除下载时，同首歌也在其他歌单/专辑下载过或单独下载过 | 保留该下载，只移除本次歌单的下载来源记录                                                     |
| ⑧    | 退出或切换账号时，仍在排队的下载                            | 保留队列；谁登录就用谁的账号去取下载地址，新账号无权完整播放的标失败并说明原因               |
| ⑨    | 断网时执行红心、加入歌单等写操作                            | 不暂存离线写队列，直接提示未修改（失败即回滚）                                               |
| ⑩    | 登录失效后换了另一个网易云账号登录                          | 清空播放队列（避免旧账号播放来源串记到新账号打卡）                                           |
| ⑪    | 下载时设备存储空间不足                                      | 暂停整个下载队列并提示一次，腾出空间后由听众点击“继续下载”从断点恢复                         |
| ⑫    | 歌单尚未同步完时播放整张歌单或下载整张歌单                  | 先使用已同步部分；同步完成后自动补齐剩余曲目（下载选歌仅勾选部分时不补）                     |

## 四条运行时不变量

1. **前台优先、后台限速与退避**：听众等待的前台请求（取播放地址、打开未同步歌单、写操作、续期）立即发出，不排在后台请求后；后台请求（增量同步、取下载地址、补发打卡）并发受控、逐页拉取。收到上游“操作频繁”时，后台按 `retryAfter` 退避，前台照常可发并在被拒时提示“稍后再试”。
2. **乐观修改叠回**：后台增量同步拿回的数据比未确认的本地写操作旧时，把本地未对上的修改叠回结果，避免刚改动的内容闪烁消失。
3. **多标签页续期互斥（Web Locks）**：同一浏览器多个标签页同时需要续期 Cookie 时加锁串行，防止第二个标签页拿刚失效的旧凭据误判登录失效。
4. **续期前请求收到 301 直接重发**：在某次成功续期之前已发出的请求若返回 301，直接用新会话重发一次，不再触发第二轮续期。

## 会话、打卡、下载与写操作边界

### 退出登录与会话失效

- **联网主动退出**：先把正在播放的歌曲按实际已播秒数打卡发出，再清除本机曲库副本与播放队列，保留已下载歌曲与排队下载。
- **断网主动退出**：断网期间积攒的未发打卡丢弃；App 立即按未登录处理不再携带凭据，但 `httpOnly` Cookie 需待重新联网后由服务端回传过期 `Set-Cookie` 清除（见 [ADR-0003](../adr/0003-credentials-in-encrypted-cookie.md)）。
- **登录失效且续期失败**：提示需要重新登录，保留播放队列、曲库副本与下载；进行中的排队同步请求须一并终止，避免同步状态卡死。失效期间可继续播放已下载歌曲（跳过未下载），打卡暂存本机：同一账号重新登录后补发，换账号则丢弃。
- **未登录播放已下载歌曲**：不记听歌打卡；登录前累计的播放秒数，登录后也不补记。

### 播放与下载边界

- **播放地址过期**：播放地址约 20 分钟过期；暂停过久或隔天重开按播放时，重新获取播放地址并从原进度续播。
- **退出时正在下载的曲目**：已经拿到直连音频地址的当前曲目继续下完；排队曲目按规则⑧等待登录后获取地址。
- **下载来源归属**：每首已下载歌曲独立记录其来源集合（可同时属于多张歌单、专辑或单独下载），不依赖曲库副本，确保未登录时仍可按歌单删除。
- **断网中断下载**：传输中遇断网保留断点，联网后自动重新排队从断点续传。

### 同步、延迟提交与换封面边界

- **增量同步与远端删除**：仅重拉更新时间变化的歌单；远端已删除的歌单同步从本地移除。向已被远端删除的歌单写入时，本地回滚并触发同步。
- **排序与批量移除延迟提交**：
  - 歌单/歌曲拖动排序先改本地，连续拖动合并延迟 2 秒提交；批量移除先从本地移除，提示条提供 5 秒撤销窗口，未撤销再提交。
  - 在延迟或撤销窗口内离开页面、切到后台或关闭页面时，立即提交（请求体 ≤ 64 KiB 用 `fetch(..., { keepalive: true })`，超限走普通请求）；提交前在本机标记未确认状态，若下次打开仍未确认则从网易云重拉该歌单并提示。
  - 写操作失败统一回滚本地副本并给重试入口。
- **红心与多选约束**：网易云红心接口仅支持单首，因此多选“加入歌单”不含“我喜欢的音乐”，我喜欢的音乐多选无“移除”动作。
- **换封面三步边界**：申请上传凭证 → 浏览器直传图片 → 设为歌单封面。输入长边超 3200px 先缩放，导出 800×800 JPEG（质量 0.88，超 1 MB 逐步降至最低 0.6）；非图片、超 20 MB、浏览器无法解码的 HEIC 明确报错。前两步允许取消并回到裁剪；第 3 步发出后不可取消，若第 3 步失败，重试只重发“设为封面”，不重复上传。
