# 按领域直接调用 SDK，只对明确的只读步骤续期重读

2026-11-11 作者审查全能 `netease.ts` 后决定拆分职责，2026-11-12 在 hana-music-api 5.0.0 正式发布后实施（#88）。沿用 ADR-0003 的加密 Cookie、ADR-0005 的独立 SDK 与公开类型，以及 ADR-0013 的 HTTP 路由。

以新建歌单为例：路由先校验名称和隐私设置，会话模块从请求的加密 Cookie 取得设备和凭据，生成本次操作的 SDK 配置。歌单模块直接调用 SDK 的 `playlistCreate`，返回编号；路由保留这个编号，再请求详情，纯转换函数把详情变成 Campanula 的歌单。如果详情返回业务 301，会话只续期并重读这个编号，已经成功的创建不能再发一次。

## 决策

- `credentials.ts` 管加密 Cookie、设备生命周期和保存。新设备用 SDK `generateDeviceId()`，已有编号继续沿用。Cookie 更新由已有库解析，纯合并函数接受旧值、下发条目和当前时间；登录和续期另外检查是否下发新的 `MUSIC_U`。
- `session.ts` 管本次操作的凭据和配置快照。`netease/config.ts` 只把明确传入的设备、凭据和部署配置变成 `ModuleCallConfig`。没有带听众身份的全局 client；续期生成新凭据和新配置，旧快照不修改。其他并发请求继续使用各自的输入。
- `netease/` 按登录、歌单、曲库、播放和搜索组织。领域函数直接调用 SDK 具名导出，接收业务参数和显式配置；数组直接交给 SDK 编码。歌曲等共用转换复用 SDK 公开类型，没有汇总转发门面和自定义 SDK 分发器。
- 映射只接收返回数据，输出 Campanula 数据；分页、缺失字段的产品兜底和已知业务结果仍由应用负责。转换不读 Cookie、不请求网络、不写日志。
- SDK 失败原样向上传递，通过公开 `getNcmFailureInfo()` 读取事实。领域可消化已知业务结果，会话可识别业务 301；常规最终失败在 `respond.ts` 统一映射并记录一次脱敏日志。App 自己发现的匿名身份、缺少必要数据有明确的应用错误，普通编程异常继续抛出。
- 默认不重放业务回调。只读请求明确传 `retryRead: true`，业务 301 后最多续期一次；依据业务语义选择，批量歌曲查询的 POST 也属于只读。包含写入的组合不能开启整个回调的重试，只把后续只读步骤交给会话提供的 `read`。创建后详情连接失败返回既有失败，不伪造成功，也不回滚远端已经完成的创建。
- 普通写入和带 `checkToken` 的写入失败均不自动续期重发。再次操作由听众主动发起，浏览器重新取得 token；token 只进入当次 SDK 配置，不保存。封面上传凭证申请也默认不重放。SDK 自身的请求策略保持由 SDK 管理。
- 打开 App 满 24 小时的主动续期、浏览器 Web Locks 的跨标签页协调、软失败保留旧凭据和退出流程继续保留。主动续期的软失败仍记录一次诊断；成功恢复的中间 301 不作为最终失败记录。

## 2026-11-13：受保护接口的 token

SDK 6.0.0 已将有官方依据的调用迁到网页地址，Campanula 不另行改写 SDK 路由。浏览器用官方反作弊配置当前匹配的业务 key `afb1a8e61222dcc4b7a733ca69f089cb` 初始化 Watchman；配置按顺序匹配、最后命中的规则覆盖前面的规则。业务 key 和端点清单一起核对，不使用 SDK 旧默认值。配置来源为 `https://music.163.com/api/middle/clientcfg/config/pushed/list?platform=web&moduleName=yidun`。

端点目录声明一次站内请求至多需要多少枚 token。浏览器在发送前逐枚取得，通过专用请求头交给服务端；URL、业务参数、加密登录 Cookie、本机副本和应用日志均不放 token。服务端为当次请求建立有限队列，只给受保护的 SDK 调用提供 provider，每次上游请求消费一枚，未用到的随请求丢弃。创建后的详情和只读重读继续用剩余的新 token，续期只消费单独预留的一枚；换凭据不重建 token 队列。

| 站内操作                                 | 业务调用预备数 | 续期预备数 |
| ---------------------------------------- | -------------- | ---------- |
| 红心/取消、简介、歌曲排序、收藏歌单/歌手 | 1              | 0          |
| 增删曲目（含 SDK 512 分支）              | 2              | 0          |
| 歌单详情、同步曲目编号（含只读重读）     | 2              | 1          |
| 创建歌单、查询详情、必要时重读详情       | 3              | 1          |
| 其他只读操作，包括 POST 批量歌曲查询     | 0              | 1          |

受保护请求取不齐 token 就不发送。其他只读操作取不到备用续期 token 时仍可查询；实际需要续期时，缺 token 明确返回安全验证不可用。取消收藏、专辑收藏、名称、标签、封面等未命中接口不向 SDK 注入 token。取值期间退出或换账号，发送前再次核对会话轮次，丢弃迟到的 token。该传递方式不改变只读重读与写入不重放的边界。

## Considered Options

- **继续包一层通用 call/invokeModule**：重复 SDK 的分发和类型配对，业务调用看不到直接入口。
- **每个领域创建 client 或 repository/service 链**：增加身份生命周期和追踪路径，没有本票需要的能力。
- **收到 301 就重跑任意回调**：创建已成功、详情失败时可能重复创建；带 token 写入也可能被重放。
- **只按 HTTP 方法决定是否重试**：批量歌曲查询用 POST，无法表示真实的读写语义。

## Consequences

- HTTP 路径、请求和响应类型、本机数据格式及产品映射保持，只有应用层重试范围明确收窄。SDK 根入口仅用于服务端适配和设备生成，浏览器继续使用 watchman 子路径及类型导入。
- App 测试与开发 mock 共用具名调用绑定，接回各自已有的录制队列和状态引擎；只有替身自身复用真实 SDK 的无网络工具，隔离探针核对全部替身导出。历史录制只在匹配处转换旧参数表示，补失败元数据时保留来源，构造场景明确标记。
- 8821 临时解析留在登录模块，只覆盖已有构造样本；真实 Schema 和样本继续跟踪 nonhana/hana-music-api#38。
- 新接模块仍先核对 SDK 公开类型和合同；缺口回 SDK 仓库处理。新增组合流程必须先划清哪些步骤已经产生远端副作用，再决定哪段可以重读。
