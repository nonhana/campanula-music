# 页面切换用浏览器的 View Transitions，不用 Svelte 的过渡或动画库

换页时，在 SvelteKit 的 `onNavigate` 里调用 `document.startViewTransition`：浏览器先拍下旧页面，等 SvelteKit 渲染好新页面，再把新旧两帧交给 CSS 做交接动画。只有内容区参与，顶栏、侧栏、播放条原地不动；原来从格子点进歌单、专辑、歌手时，被点的那张封面和页头的大封面用同一个名字飞过去，2026-10-31 作者定去掉（见文末）。方向（进入下一层、返回、同一层之间）用 View Transitions 的 `types` 交给 CSS。动效方向 B「封面是主角」由作者在 2026-10-14 选定，规则写在 DESIGN.md。Campanula 只支持 Chrome 和 Edge（PRODUCT.md），它们早已支持同一文档内的 View Transitions；其他浏览器直接换页，没有动画，功能不受影响。

## Considered Options

- **Svelte 的 `transition:`**：页面是 SvelteKit 换掉的组件，过渡默认是局部的，放在页面根节点上换页时不播放；改成全局后，飘出期间新旧两页同时在文档里，页面高度、滚动位置、按窗口计算的虚拟列表都会乱。
- **动画库（Motion、GSAP）**：同样要让新旧两页同时挂着，封面飞行还要自己量位置；多一个依赖，做的是浏览器已经能做的事。
- **自己克隆封面飞过去**：点歌时歌曲行的封面飞进播放条就这么做（不换页，播放条一直在）。换页时自己克隆要处理滚动、裁切、两头的层级，等于重写一遍 View Transitions。

## Consequences

- 同一时刻文档里一个名字只能有一个元素。桌面歌单页的左栏只在左栏换歌单（`fade`）时起名（`html:active-view-transition-type(fade)` 下才有名字）、带 `still`：左栏原地放新的一帧，当前这张换底色、滚到正中都是活的；平时不起名，从曲库进来时它跟着整页飘入。
- 内容区用根元素（root）的快照，不给内容区单独起名（#49 实现时改）：页面是窗口在滚（ADR-0012），给 `main` 起名的话，浏览器按它在视口里的位置拍，滚过的页面拍出来位置不对，新旧两页对不上。整个视口的快照不受滚动位置影响；顶栏、侧栏、播放条、播放提示各自起名、带 `view-transition-class: still`，不在快照里，原地不动，新的一帧是活的（进度线照常走）。
- 格子和详情页头的封面按同一个尺寸取缩略图（`src/lib/components/library/tile-grid.ts` 的 `TILE_COVER_SIZE`，200px，取 400px 的图），从格子点进去时页头的图已在缓存里，跟着新页一起出现，不从薄荷底淡入。歌单页左栏是 40px 的行，页头先铺左栏那张小图（`Cover` 的 `placeholder`），大图到了再淡上去。
- 浏览器自带的交叉淡化靠 `mix-blend-mode: plus-lighter` 把新旧两张叠成一张，它是默认 `animation` 里的一项（`-ua-mix-blend-mode-plus-lighter`）。CSS 里改写了某个名字的 `animation`，就要自己写上 `mix-blend-mode: plus-lighter`，不然淡到一半两张都半透明、透出底色，两页一样的地方也会闪（#50 发现：桌面歌单页左栏换歌单时，整个内容区像刷新了一下）。
- 浏览器拍新页面之前，要等 SvelteKit 渲染完、滚动位置恢复完。`snapshot.ts` 用 `$app/navigation` 的 `snapshot()`，每页显式传路由 id，页面状态和滚动位置同次注册：恢复状态后当场画好、当场滚，过渡等 `navigation.complete` 就够了。页面晚于会话检查挂载时也由助手在 `onMount` 恢复；歌单切换清搜索词留在 `afterNavigate`，不放到浅路由也会触发的 `reset` 里（#63）。
- Android 上 Chrome 的系统返回手势可能自己放一段“预览上一页”的动画（`hasUAVisualTransition` 为真），这时跳过我们的，免得叠两层；要在真机上确认。
- 过渡中又换了页，用 `skipTransition()` 直接结束上一个，不排队。过渡中 Chrome 把所有点按都交给 `<html>`，链接、按钮点不到：按下时结束过渡，松开后的点按交给手指下面真正的元素，快速连点照常生效。
- 播放页的开关是浅路由，页面过渡跳过它，继续由抽屉负责。Kit 3.1 的浅 `goto` 会触发导航回调，浅返回只更新 `page.state`；浮层栈的 history 适配器统一观察这个状态（#64）。
- 减少动态效果时，换页只做 150ms 的交叉淡化，没有位移。

## 2026-10-31：去掉换页时的封面飞行

作者实际使用后定：从格子飞到页头的封面看着别扭，实现也复杂（起飞、降落两头找同名的封面，等图加载、解码，判断封面露没露在屏幕里，记住从哪些格子点进来好飞回去），桌面歌单页左栏换歌单时，左栏被点的那一格在旧的一帧里留下空洞、页头的封面位置要等飞行落地才有图，看起来整页闪了一下。去掉以后换页只剩整页的飘入飘出和交叉淡化；点歌时那一行的封面飞进播放条不受影响（不换页，不走 View Transitions）。
