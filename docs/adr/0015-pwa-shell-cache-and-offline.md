# PWA 外壳：Service Worker 只缓存外壳，更新等下次打开，断网用本机副本打开

Spec #11「离线、安装与更新」要求桌面和手机都能装成独立窗口、手机锁竖屏、断网能打开并提示离线、新版本在下次打开时生效且不打断正在播放的歌（#42）。manifest 和安装提示交给浏览器，我们自己只决定两件事：缓存什么、什么时候换版本；以及断网打开时显示什么。

## 缓存什么

`static/manifest.webmanifest` 声明 `display: standalone`、`orientation: portrait` 和 192/512 的图标（另有一张 maskable）。Service Worker（`src/service-worker/index.ts`）在安装时把 `$app/manifest` 的构建产物、`static/` 和外壳页面（`/`）整份存进一个按构建版本命名的缓存。

- 页面导航先走网络、断网时回退到存下的外壳：打开 App 时总是拿部署后的最新版本，断网时 SPA 自己按地址画页面。
- 构建产物和 `static/` 先看缓存：断网时脚本、字体、图标都从这一份里来。
- 只处理同源 GET；`/api/**`、网易云的音频和图片一律不经过 Service Worker，也不缓存。歌曲播放和下载本来就是浏览器直连网易云（Spec #11 架构），缓存它们会破坏断点续传和会员权益的判断。
- 网络拿到的 HTML 不写回缓存：它可能指向这份缓存里还没有的新构建产物，断网时会加载失败。

## 什么时候换版本

Service Worker 不在 `install` 里 `skipWaiting`。新版本装好以后停在 waiting，等所有标签页关掉后再生效；`activate` 时删掉旧的缓存、`clients.claim()`。

这样部署新版本时，正在播放的那一页继续用旧的外壳和旧缓存里的脚本，音频不受影响；下一次打开 App 才用上新版本。App 不订阅 SvelteKit 的 `updated`，也不在检测到新版本时 `location.reload()`，所以没有“更新提示”打断听众。

## 断网打开

Service Worker 只保证外壳能加载；打开后还要先问服务端当前账号（登录续期就在这一步）。断网时问不到，App 用本机 SESSION 存储里上次登录的账号先进入本机副本（ADR-0007）：曲库、播放队列和下载都从 IndexedDB 读，联网后后台同步接着跑，服务端仍会在下一次请求里续期或回“需要登录”。

本机没有账号时（从没登录过、退出过，或旧版本还没记过账号）当作未登录：登录页和已下载的歌照样能看、能放（ADR-0006），不会拿别人的副本冒充。

三个外框（登录后、未登录的已下载页、登录页）在断网时顶栏下面贴一条蜜桃色的“网络已断开，只能播放已下载的歌”；联网后自己消失。

## Consequences

- 第一次打开必须联网装好外壳；之后断网打开用的是上一次生效的版本，不是最新部署。
- 发布新版本后，已经打开的标签页会继续用旧版本，直到全部关掉；这是有意为之，换来更新不打断播放。
- Service Worker 在开发服务器里不注册缓存（`dev` 时什么都不做），在 `pnpm dev:mock` 里看不到断网外壳；验证要跑生产构建。
- 本机账号只是“上次登录的是谁”，不是凭据；真正的 Cookie 仍只在服务端的加密 Cookie 里（ADR-0003）。退出登录、服务端说未登录时都删掉本机账号。
