# 视觉原型的结论

> 原型分支 `prototype/visual`，从 `rewrite/v1` 的 `250cad4` 切出，2026-10-07。分支不合回 `rewrite/v1`；进 `rewrite/v1` 的只有 `PRODUCT.md`、`DESIGN.md` 和这份结论。

## 要回答的问题

Campanula 在手机和桌面上应该长什么样？要求：只用一套设计系统；手机借 Auxio 的交互方式，桌面以原来的 Campanula 为蓝本；覆盖简报第一部分列出的 11 类界面。

## 结论

**选定方案 A“分区首页”，并从 B 拿来三样：波浪进度条、胶囊按钮、播放页用封面颜色染底。** 设计系统写在 `DESIGN.md`，北极星是“清晨的风铃草”；产品背景写在 `PRODUCT.md`。两份手机和桌面共用。

- **桌面**：骨架沿用原来的 Campanula（64px 顶栏、72px 图标侧栏、80px 底部通栏）。打开是整个曲库的分区总览：我喜欢的音乐（三行横向歌曲格）、每日推荐方块、歌单、专辑、歌手。
- **手机**：照 Auxio 的交互：顶部文字标签（我喜欢 / 歌单 / 专辑 / 歌手）、Auxio 式歌曲行、浮起的迷你播放条、底部弹层。
- **签名动作“晨光行”**：正在播放的那一行，一层浅薄荷光从歌名开始，随播放进度往右铺开。

## 选了什么、否掉了什么、为什么

第一轮用 impeccable 的抽签工具（`concept-seed`，seed `7b599941`）抽出三个结构不同的方向。三者用同一套颜色、字体、圆角，只在“界面怎么组织”上不同：

| 方向 | 做法 | 结果 |
|---|---|---|
| **A · 分区首页** | 桌面打开是曲库分区总览，是原来首页的进化；签名是晨光行 | **选中**：最像现在的 Campanula，一眼能看到整个曲库，离“点一首就响”只有一步 |
| B · 歌词舞台 | 左侧一列安静的分类，打开就是完整列表；播放页被封面颜色照亮，整屏逐字歌词 | 整体**否掉**：曲库首屏太素，没有总览。**留下**它的波浪进度条、胶囊按钮、封面染底 |
| C · 搜索脊梁 | 顶部薄荷色带放搜索框，边打字边出结果，进歌单就只在歌单里搜；桌面是可排序的密集表格 | **否掉**：观感偏工具，最接近站长说的“太素，像系统设置” |

站长另外定了几件事：
- 不要手机右下角的“随机播放”悬浮按钮（A 原本有）。
- 曲库第一个标签显示“我喜欢”，页面标题仍写“我喜欢的音乐”（已写进 `PRODUCT.md`）。
- logo 保留原图形，不再旋转。

## 原型里验证过的事

- **字体**：
  - 原来只加载了 300、400 两个字重，所有粗体都是浏览器模拟的。
  - Google Fonts 按字符切片，SC → TC → JP 的回退顺序会让假名间距不均。
  - 改用随项目打包的 Noto 可变字体，并按文字给元素标 `lang`。字体检查页逐字测过，假名字宽一致。
- **对比度**：
  - 原来的薄荷底白字只有 1.65:1，珊瑚底白字只有 2.98:1。
  - 现在的配色里，文字至少 4.5:1，图标和进度线至少 3:1。具体数值写在 `DESIGN.md`。
- **4,815 首**：只渲染看得见的几十行，滚动、歌单内搜索都即时。
- **单击播放、右键菜单**：
  - 三种布局都实测了一次点击就播放。
  - 窄窗口里用鼠标右键，仍是浮动菜单；触屏用底部弹层。
- **impeccable 独立审查**：结论是“需要修”，共 8 条，已全部改完：
  - 晨光行看不见：光藏在了封面下面，封面又被一层浅色盖住。
  - 首页歌曲格做成了四行，契约写的是三行。
  - 三处用了近黑色的实心按钮，超出了这套颜色。
  - 空状态文案用 `•••` 字符代替图标。
  - 桌面搜索用了居中弹窗；已改成顶栏搜索框挂下拉，结果在内容区单独成页，和官方客户端一致。
  - 空歌单的头部首数和下面的列表对不上。
  - 手机专辑页的收藏按钮没有文字。
  - 横向歌曲格露出的半列被硬切。

## 交给主会话的问题（原型里没有拍板）

1. **平板宽度**：原型只用 768px 一个断点区分手机和桌面布局，并验证了“窄窗口用鼠标仍有右键菜单”。平板的具体布局要在 Spec 里定。
2. **桌面搜索的交互是照官方定的**：顶栏框里打字出建议，按搜索后结果在内容区单独成页。这和原来 Campanula 的居中搜索弹窗不同。按 ADR-0002，偏离官方的交互要先经原型验证，这里是回到官方的做法，请主会话确认。
3. **在搜索结果里点一首歌**：原型照官方做法，把它插到当前歌后面立即播放，不替换播放队列。逻辑原型的 3.1“在列表里点一首歌”说的是普通列表，搜索结果属于哪种，需要在逻辑原型或 Spec 里写明。
4. **歌单标签**：原型里的标签列表和上限 3 个，是凭网易云官方客户端的印象写的，实现前要用 hana-music-api 的真实接口核对。
5. **封面图**：原型的封面从旧站截图里裁出来，分辨率很低。正式实现用网易云原图，不影响设计。

## 原型分支在原型目录外改了什么（旧代码删除时一起消失）

- **`src/routes/+layout.svelte`**：
  - reset 改为先于 `uno.css` 加载。原来的顺序会让带 `type="button"` 的按钮丢失底色，新代码也要注意这一点。
  - `/prototype` 下的页面不套旧外壳。
- **`uno.config.ts`**：
  - 加了 `shadow-ambient`、`shadow-float` 两档阴影（DESIGN.md 用到）。
  - 关掉了启动时去 Google 抓字体。抓取超过 2 秒，dev server 会崩溃。
- **`package.json`**：加了 4 个 `@fontsource-variable/noto-sans*` 开发依赖。
