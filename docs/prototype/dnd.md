# 交互原型的结论

> 原型分支 `prototype/dnd`，从 `rewrite/v1` 的 `8b51fed` 切出，2026-10-07。分支不合回 `rewrite/v1`；进 `rewrite/v1` 的只有这份结论。

## 要回答的问题

1. **拖拽排序和批量操作**（简报 2.1）：在几千首的歌单里，拖拽排序和批量操作在手机和桌面上手感对不对？用哪个库？
2. **封面裁剪和上传**（简报 2.2）：换封面的流程顺不顺？

## 结论

站长 2026-10-07 在 Android 手机和桌面上实际试过后定下：

- **实现：自己用 pointer events 写**，不用 svelte-dnd-action，也不用 dnd-kit。
- **拖拽方案：C 编辑模式。**
  - 歌单里：点“多选 · 排序”（桌面叫“批量操作 · 排序”）或长按一行，进入编辑模式；勾选和拖动把手都在这个模式里。平时歌曲行上没有把手，单击照常播放。退出：手机点左上角的关闭或用返回手势，桌面点“完成”或按 Esc。
  - 桌面上不进编辑模式，也能用 ⌘ / Ctrl 点选、Shift 连选，再批量操作；拖动排序只在编辑模式里按把手。
  - 曲库里的自建歌单：点“排序”，封面格子换成列表，按每行右边的把手拖，点“完成”退出。
- **批量移除：直接移除，提示条里可以撤销。** 先从本地拿掉（ADR-0007），提示条留 5 秒，没撤销才提交给网易云；提交失败就把这几首放回原位，并说明。
- **换封面：A 单独的裁剪页。** 手机全屏、桌面大弹窗。点“使用”后，在同一页里显示三步上传的进度；取消就回到裁剪，成功才关闭。

## 选了什么、否掉了什么、为什么

### 实现

数据来自 1440×900 桌面 Chromium（有窗口，每秒 90 帧；无窗口时只有每秒 15 帧，自动滚动的数据不可信）。

| | **自写（选中）** | svelte-dnd-action 0.9.80 | dnd-kit（`@dnd-kit/svelte` 0.5.0） |
|---|---|---|---|
| 把第 10 首拖到第 3,000 首（拖到边缘自动滚动） | 14.9 秒到达；最快 273 行/秒，停在边缘会继续加速 | 45 秒只到第 1,219 首：只认滚动区边缘 30px，每帧最多 30px，不能调 | 45 秒到第 2,052 首：加速度可调，但停在边缘不会加速 |
| 快速定位 | 拖到右侧窄条按比例跳：1.6 秒跳到第 3,117 首，约 6 秒精确落到第 3,000 首 | 没有 | 没有 |
| 一次拖多首 | 支持：勾选的几首一起拖，保持先后顺序 | 不支持（只有示例） | 不支持 |
| 手机：屏幕底部被浮起的播放条盖住 | 边缘区从播放条上沿算起，照常滚 | 边缘区固定在屏幕边上，被播放条盖住：曲库里拖到播放条上方完全不滚 | 能滚（边缘区是屏幕高度的 15%） |
| 配合虚拟列表 | 自己控制；被拖的那个节点一直保留，Android 上手指底下的元素不会被卸载 | 要求拖放区的子元素和数据一一对应：只能做“流式窗口”，拼接时还要原样传回库的影子标记，否则松手后顺序不变 | 被拖的行要一直挂载，能做 |
| 整行是一个按钮 | 没影响 | 不肯从按钮上开始拖，只能改成由外层接住点按 | 传感器必须传给每一行；传给外层的 `DragDropProvider` 不生效，按在行上拖不起来 |
| 触屏轻点 | 正常 | 库自己再补发一次 click，要去重；松手后要等 150ms 的落位动画才发 finalize，紧接着的一次轻点会被当成“播放” | 正常 |
| 代价 | 原型约 940 行（歌曲列表 685 行、曲库格子 257 行），正式版要自己写测试和键盘操作 | 现成，但上面每一条都要绕 | 还没到 1.0，Svelte 版的用法还在变 |

三种实现在模拟触屏下都做到了：快速滑动是滚动，长按后挪动是排序，长按不动就松手是进入多选，按住把手立即拖。差别在上表：只有自写的能同时做到一次拖多首、自动滚动的速度和边缘区可调、快速定位；两个库在“4,815 首的虚拟列表 + 整行是按钮”这个场景里都要绕好几个坑。

### 拖拽方案

| 方案 | 做法 | 代价 | 结果 |
|---|---|---|---|
| A 长按拖动 | 长按一行浮起，接着挪就是拖，原地松手就进入多选 | 长按同时管“拖”和“多选”，手指一抖就可能变成拖 | 未选 |
| B 拖动把手 | 每行常驻把手，按住立即拖 | 每张自建歌单的每一行都多一个控件，手机上歌名少 44px | 未选 |
| **C 编辑模式** | 先进编辑模式，勾选和把手在同一个模式里 | 要多点一下才能拖 | **选中** |

### 批量移除

- **直接移除，提示条里撤销**：选中。
- 先弹确认再移除：未选。确认弹层的样子见截图 `dnd-remove-confirm`，原型面板里仍能切换。

### 换封面

| 方案 | 做法 | 特点 | 结果 |
|---|---|---|---|
| **A 单独的裁剪页** | 手机全屏、桌面大弹窗裁剪，同一页里显示上传进度 | 裁剪框最大（手机 342px）；取消回到裁剪，成功才关闭 | **选中** |
| B 自动居中，可再调整 | 选图后直接按居中裁好上传；提示条里有“调整”和“撤销” | 最快，但边界最多：上传中点“调整”要停下上传；“撤销”要再写一次网易云 | 未选 |
| C 弹层里原地裁剪 | 底部弹层（桌面是弹窗）里裁剪、上传、看结果 | 不离开歌单页，但裁剪框小（手机 294px），上传时弹层一直开着 | 未选 |

## 交付物

- **运行**：`pnpm dev`，打开 `/prototype/dnd`（拖拽和批量）、`/prototype/dnd/cover`（换封面）。窗口窄于 768px 是手机布局。真机：`pnpm dev --host`，手机连同一个 Wi-Fi，打开 `http://<这台 Mac 的局域网 IP>:<端口>/prototype/dnd`。
- 底部的黑色切换栏：‹ › 切方案，中间切实现，右边的按钮打开原型面板。弹层开着时，它缩成右上角的一个按钮。
- **原型面板**：假接口成功或失败（看回滚）、批量移除的方式、长按时长、自动滚动的速度、加速和边缘区、快速定位开关、上传哪一步失败、上传速度、测试文件（横图、竖图、8000×6000、超过 20 MB、200×200、HEIC、不是图片），以及请求记录、上一次拖动的统计。
- **网址参数**：

  | 参数 | 作用 |
  |---|---|
  | `variant=A\|B\|C` | 拖拽页：长按拖动 / 拖动把手 / 编辑模式；封面页：单独的裁剪页 / 自动居中可再调整 / 弹层里原地裁剪 |
  | `engine=action\|kit` | 换成 svelte-dnd-action / dnd-kit（不写是自写） |
  | `screen=library` | 曲库里的自建歌单排序 |
  | `pl` | 打开哪张歌单（默认是 4,815 首的自建歌单「ACG 大合集」；封面页默认是 7 首的「一起看海」） |
  | `shot=1` | 截图模式：不显示切换栏 |

- **截图**：`prototype/dnd` 分支上的 `static/prototype/shots/dnd/`（不进 `rewrite/v1`），30 个画面，手机（390×844）和桌面（1440×900）各一张，共 60 张，都用自写的实现。选定的方案：
  - 拖拽 C：`dnd-C-edit`（编辑模式）、`dnd-C-drag`（按把手拖）、`dnd-C-multi`（勾 3 首一起拖）、`dnd-C-rail`（快速定位）、`dnd-rollback`（提交失败后回滚）。
  - 批量（都在方案 C 下）：`dnd-select`（手机长按进入，桌面 ⌘ 点选）、`dnd-add`、`dnd-remove-undo`。
  - 曲库排序 C：`lib-C-sort`、`lib-C-drag`。
  - 封面 A：`cover-A-crop`、`cover-A-upload`、`cover-A-fail`、`cover-small`、`cover-heic`、`cover-too-big`。
  - 其余是没选中的方案，留作对照：`dnd-A-list`、`dnd-A-drag`、`dnd-A-multi`、`dnd-A-rail`、`dnd-B-list`、`dnd-B-drag`、`dnd-remove-confirm`、`lib-A`、`lib-A-drag`、`lib-B`、`cover-B-uploading`、`cover-B-done`、`cover-C-crop`、`cover-C-done`。

## 原型里验证过的事

- **提交和回滚**（ADR-0007）：
  - 拖完先改本地，等 2 秒没再拖才提交；连拖两次只提交一次。离开歌单、切到后台、关页面时立即提交，不等计时器。`song_order_update` 一次带全部 4,815 个编号，请求体约 52 KB。
  - 假接口失败时退回原来的顺序，提示里有“重试”，重试后恢复刚才的顺序。曲库里的 `playlist_order_update` 同样合并、回滚。
- **桌面**：单击仍是播放；⌘ / Ctrl 点选、Shift 连选；多选工具条出现时下面的行不跳；拖动中按 Esc 取消；焦点在某一行时 Alt + ↑ / ↓ 移一位。
- **批量操作**：
  - 加入歌单的目标只有“新建歌单”、我喜欢的音乐（标“等于红心”）和自建歌单；当前歌单不可选；收藏的歌单不出现。
  - 收藏来的歌单没有“移除”；我喜欢的音乐里的“移除”叫“取消红心”。
  - 下载自动跳过已下载、试听、无版权的歌，并逐项说明（例：“已加入下载 1 首；3 首已下载过；1 首试听歌曲不能下载；1 首无版权”）。
  - 无版权的歌在多选里也能勾（只是不能播、不能下载）。原型里起初勾不上，已改。
  - 长按进入多选后马上连点几首，每一下都算数。原型里起初会吞掉紧跟着的那一下，已改。
- **曲库里自建歌单排序**：三种实现 × 三种方案，桌面鼠标和模拟触屏都能拖；轻点一张歌单正好打开一次；快速滑动是滚动。我喜欢的音乐固定在最前，收藏的歌单不参与。
- **封面**：
  - 不是图片、超过 20 MB、HEIC（Chromium 解不开）：说清楚为什么不能用，给“换一张图片”。
  - 8000×6000 的图先缩到长边 3200px 再裁（194 ms）；200×200 的图能用，但提示可能会糊。
  - 导出 800×800 的 JPEG，质量 0.88，超过 1 MB 就降质量重压，最低 0.6。测试图导出 86–133 KB。
  - 三步（申请上传凭证 → 浏览器直传 → 设为封面）各自失败都有对应的说明；第 3 步失败后重试只再设一次，不重新上传。
  - 第 1、2 步可以取消，取消后回到裁剪；第 3 步已经发给服务器，按钮变成“正在设为封面”，不能取消。
  - 取景框：一指拖动、两指捏合（模拟触屏放大到 2.5 倍）、滚轮、滑块、方向键；拖动时页面和弹层都不滚。
- **站长真机试用后改的**：
  - 手机上拖动时，“移到第 N 首”的标签下半截被浮起的那一行盖住（站长的真机截图）：浮起的行自带层级，标签没有。已把标签提到最上层，手机和桌面都复查过。
  - 拖动时，其余行右边的“更多”按钮和快速定位窄条叠在一起（同一张截图里能看到）：手机上拖动时，这些按钮淡出。
  - 方案 C 在手机上的把手正好落在快速定位窄条里：按住把手往下拖 3 行，被当成快速定位，一下跳到第 2,841 首。这是选定 C 以后复查时发现的。改成：从窄条里开始拖，要先往左离开窄条，快速定位才接手；“拖到这里快速定位”的提示也等离开以后再出现。改后按把手往下拖 3 行正好落在第 6 首，先往左挪再拖回窄条照常快速定位。正式实现要保留这条规则。
- **原型里用的默认值**：长按 400 ms；提交前等 2 秒；自动滚动最快 1,600 px/秒，停在边缘 3 秒内最多加速到 8 倍，边缘区 72px；批量移除的撤销窗口 5 秒。
- **impeccable 机械检查**：快速定位条的宽度动画改成了 `scale`，一处圆角对齐到 12px。剩下的提示是原型切换栏（原型专用），和 DESIGN.md 字号阶梯之外的 12 / 16 / 17 / 18 / 22px（视觉原型 A 里同样在用），见下面第 8 条。

## 交给主会话的问题

1. **一次提交 4,815 个编号，网易云接不接受**（约 52 KB）。验证关卡可以这样测，不碰已有歌单：临时歌单里批量加入约 5,000 首 → 排一次序 → 删掉歌单。`playlist_tracks` 一次最多能加多少首，也顺便测出来；加歌要按每秒 2 次的配额分批。
2. **我喜欢的音乐能不能手动排序**：没核实。原型里不能拖。
3. **批量红心能不能一次提交**：原型当成一次请求。如果红心接口一次只能一首，批量“加入我喜欢的音乐”要按配额排队（50 首约 25 秒），界面要显示进度。
4. **`playlist_cover_update` 能不能直接传已上传图片的编号**（`decisions.md` 第 5 节已列为要改的地方）：第 3 步失败后“重试只再设一次”靠它。
5. **封面的输出尺寸和大小上限**：没核实，原型固定 800×800、不超过 1 MB。
6. **HEIC**：桌面 Chromium 解不开。Android 的照片选择器交给网页的是 HEIC 原图还是转好的 JPEG，要在真机上看。
7. **官方客户端怎么排序、怎么换封面**：原型没对照。按 ADR-0002，偏离官方的交互要先经原型验证；这次站长已在真机上验证并选了拖拽 C、封面 A，如果和官方不同，主会话记一笔即可。
8. **字号阶梯**：DESIGN.md 只有 11 / 13 / 14 / 15 / 20 / 28 / 56px，两个原型都用了 12、16、18px 等。要么 DESIGN.md 补上这几档，要么实现时对齐到现有阶梯。
9. **措辞**：进入编辑模式的按钮，桌面写“批量操作 · 排序”，手机写“多选 · 排序”；“多选”“批量操作”“编辑模式”都不在 `GLOSSARY.md` 里。选了 C 以后，这个按钮是排序和批量操作的主要入口，建议统一成一个词再写进术语表。
10. **Android 返回手势**：原型里多选模式会压一条浅路由历史，返回键先退出多选、再离开页面。要在真机上确认。
11. **撤销窗口里离开页面**：批量移除先从本地拿掉，5 秒后才提交。这 5 秒里切到后台或关掉页面，正式实现要像排序一样立即提交；否则这次移除会丢，下次同步以网易云为准，这几首又会回来。原型里排序已经这样做，移除没做（原型不保存数据）。

## 原型分支在原型目录外改了什么（旧代码删除时一起消失）

- 视觉原型带过来的基础设置，同 `docs/prototype/visual.md`：`src/routes/+layout.svelte`、`uno.config.ts`、`package.json` 里 4 个 `@fontsource-variable/noto-sans*` 开发依赖。
- **`package.json`**：为了比较，加了 `svelte-dnd-action` 0.9.80，以及 `@dnd-kit/svelte`、`@dnd-kit/dom`、`@dnd-kit/abstract` 0.5.0 三个开发依赖。选定了自写，正式代码一个都不用。
