本页概述 Campanula 的系统分层与核心机制，本地启动见[本地开发](./index.md)。

## 系统分层

Campanula 基于单一 Svelte 5 + SvelteKit 工程构建，前端关闭服务端渲染（SSR），以 SPA / PWA 形态运行；服务端仅承担无状态 API 转发职责，并按目标平台切换构建适配器：

| 层级        | 核心目录 / 模块                             | 职责说明                                                                                 |
| ----------- | ------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 视图与交互  | `src/routes/**`、`src/lib/components/`      | 响应式桌面/手机骨架、播放页与列表视图，不直接发请求                                      |
| 客户端核心  | `src/lib/app/`                              | 封装状态机、播放队列、下载管理、本地缓存与同步调度                                       |
| 端点契约    | `src/lib/api/`                              | 前后端共享的请求路径与类型契约                                                           |
| 轻量 API 层 | `src/routes/api/**/+server.ts`              | 解密加密 Cookie 并调用 [`hana-music-api`](https://github.com/nonhana/hana-music-api) SDK |
| 运行适配器  | `@sveltejs/adapter-vercel` / `adapter-node` | 分别面向 Vercel (`hkg1`) 与自建服务器单进程构建产物                                      |

## 请求与媒体数据流

应用通过「轻量接口走实例、大流量媒体直连上游」的分离模型消除站长服务器的带宽瓶颈与无状态会话持久化压力：

```text
[浏览器应用]
   ├── 业务接口 ──▶ [实例 API 层] ──▶ [网易云接口]（加密 Cookie 解密即弃）
   └── 音频播放 / 下载 / 歌单封面上传 ──直连──▶ [网易云存储节点]
```

- **凭据隔离**：服务端不落盘、不建库；请求到达后使用 `COOKIE_SECRET` 现场解密 Cookie 并发起上游调用。
- **双环境隔离开发**：`scripts/dev.mts` 分别为真实环境（`local.campanula.test:8443`）与 Mock 环境（`mock.campanula.test:8444`）提供独立主机与隔离的 Cookie 作用域，Mock 装配与生产产物完全分离。

## 核心客户端机制

| 机制               | 设计方案                                        | 解决的核心问题                                         |
| ------------------ | ----------------------------------------------- | ------------------------------------------------------ |
| IndexedDB 本地优先 | 启动即渲染本地曲库副本，后台增量同步并做乐观写  | 消除等待首屏请求延迟，大歌单列表与搜索可在本地瞬时筛选 |
| 队列分级调度       | 前台切歌优先，后台同步走低优先级限速队列        | 避免大曲库增量拉取阻塞当前点播与界面操作               |
| 双 `<audio>` 接力  | 播放当前曲目时空闲实例预缓冲下一首并无缝接力    | 防止 Android Chrome 切歌瞬间丢失音频焦点导致后台停播   |
| 页面内流式断点下载 | 打开中的页面分段写入本机存储并持久化断点        | 规避浏览器 Background Fetch 的状态误报与整批失败       |
| 浏览器侧标签写入   | 导出时现场写入 MP3/FLAC 标签、封面图与歌词      | 导出的普通音频副本可直接在外部播放器完整显示元信息     |
| 外壳延迟更新（SW） | Service Worker 仅缓存应用外壳并在下次重开时激活 | 避免新版本部署时刷新打断正在进行的歌曲播放             |
